# Phase 1 — Asset Library and Secure Context

**Outcome:** asset manager works at `https://guides.henning.rodeo`, fails clearly on unsupported HTTP LAN origins, and ships with a deterministic demo asset set.

## Task 1.1 — reproduce before changing code

Test these origins in a real browser:

```text
http://localhost:1420/assets
http://192.168.1.40:1420/assets
https://guides.henning.rodeo/assets   # once staging route exists
```

Capture:

```js
window.isSecureContext
typeof globalThis.crypto
typeof globalThis.crypto?.subtle
typeof globalThis.crypto?.randomUUID
```

Then click one procedural asset and record the exact stack trace.

**Acceptance:** the report proves whether the failing call is `crypto.subtle.digest`/secure-context related. Do not close this task with “probably.”

## Task 1.2 — add a central browser capability probe

Create a small focused browser utility, e.g.:

```text
apps/web/src/services/browserCapabilities.ts
```

Interface:

```ts
export interface BrowserCapabilities {
  secureContext: boolean;
  webCrypto: boolean;
  randomUuid: boolean;
  opfs: boolean;
}

export function getBrowserCapabilities(): BrowserCapabilities;
export function assertAssetStorageSupported(): void;
```

`assertAssetStorageSupported()` must return a human-actionable error similar to:

```text
Asset storage requires a secure browser context. Open GuideForge over HTTPS
(or localhost for development). Current origin: http://192.168.1.40:1420
```

Do not introduce a bespoke cryptographic implementation merely to hide an insecure deployment.

Tests:

- secure + crypto present -> succeeds;
- missing `crypto.subtle` -> deterministic actionable error;
- OPFS missing -> storage can still report fallback behavior if IndexedDB is valid;
- asset page renders the message rather than an uncaught exception.

## Task 1.3 — harden storage error semantics

`packages/storage-web/src/index.ts` should not emit a vague `Cannot read properties of undefined` when SHA-256 is unavailable.

Add a named error or explicit precondition around Web Crypto before `digest()`.

Example contract:

```ts
export class SecureContextRequiredError extends Error {
  readonly code = 'SECURE_CONTEXT_REQUIRED';
}
```

Unit test the error code/message.

## Task 1.4 — make seed assets idempotent

Use existing `SEED_CATALOG`.

Add a service function such as:

```ts
export async function ensureSeedCatalog(
  library: AssetLibrary,
): Promise<{ created: number; existing: number }>;
```

Requirements:

- deterministic generated bytes remain content-addressed;
- repeated runs do not duplicate storage;
- failures identify the template that failed;
- seed provenance remains `CC0` / procedural;
- do not download third-party assets merely to populate the demo.

## Task 1.5 — first-run Asset Manager UX

On `/assets`:

- show storage capability status;
- show a “Load demo asset catalog” action if seed inventory missing;
- after seed, show at least 5 visually distinguishable entries;
- show format, size, provenance/license, review state;
- provide a lightweight preview/turntable only if the existing renderer can do it safely without derailing the phase.

Do not make asset thumbnails a blocker for the secure-context fix.

## Task 1.6 — E2E over HTTPS

Add browser test covering:

1. fresh browser profile;
2. open `/assets`;
3. seed catalog;
4. verify entries appear;
5. refresh;
6. verify entries still exist and are not duplicated;
7. import one tiny known-safe fixture GLB;
8. verify SHA-256 metadata is displayed;
9. no page/console errors.

**Phase gate:** no “crypto” error on the actual HTTPS deployment. LAN HTTP shows a clear unsupported-origin message instead of crashing.
